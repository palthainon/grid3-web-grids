# Muse grid set evaluation (2026-11-08)

Evaluated: `grids/Muse.gridset` as published on `main` at de6ea50 (dark cells, keyboard Back fix). Method:
`tools/evaluate-gridset.ps1` on the built set, `tests/site-audit.js` on the live muse.ai page in Chrome
(signed in, read-only), and the checklist in `.claude/skills/accessibility-review/SKILL.md`. Nothing here was
tested on a Grid 3 device.

## Ranked improvements

Built on 2026-11-08 (PR 23): items 1 to 4, at the operator's request. More Tools got one group per column,
which fits its layout better than rows. Worst cases now: Keyboard and Punctuation 13 steps, More Tools 9.
Not yet seen in Grid 3.

1. **Put Back at 0,0 on More Tools.** Back is at 0,0 on every keyboard grid, but at 9,5 on More Tools. On More
   Tools, 0,0 is Grid explorer, which leaves Muse. A press from habit takes the user out of the grid set.
   Change: Back to 0,0, Grid explorer to 9,5. Gain: one Back position everywhere. Risk: low. The user does
   not need to try it first.
2. **Give keys without text an AudioDescription.** The space bar on Keyboard and Keyboard - Punctuation has
   no text, and Enter, Left and Right on Keyboard - Punctuation show only images. With auditory scanning they
   may say nothing. Change: AudioDescription "space", "enter", "left", "right" (as Smartbox's Text Talker
   keyboard does). Gain: every key speaks. Risk: none. Check on a device that Grid 3 speaks them.
3. **Split the long scan groups on Keyboard - Punctuation and More Tools into rows.** Punctuation is one group
   of 40 cells (41 steps worst case). More Tools is one group of 18. Change: one group per row (about 10 cells
   each), most used row first. Gain: worst case about 15 steps on Punctuation. Risk: a new scan order. Try it
   with the user.
4. **Consider row groups for the keyboard letters.** The letters are one group of 29 cells (31 steps worst
   case). This copies the user's email keyboard, which they know. Change: one group per letter row. Gain:
   worst case about 13 steps. Risk: it differs from the email keyboard. Ask the user first, and change both
   keyboards or neither.
5. **Check the scan highlight on the dark cells.** The highlight colour is a Grid 3 access setting. It must be
   at least 3:1 against the dark cells (WCAG 1.4.11). Check on the device.
6. **Name the scan groups (test first).** No grid names its scan groups in `ScanBlockAudioDescriptions`, and
   no stock grid set does either. Untested whether Grid 3 speaks a group's name. Try it in a test set on the
   operator's machine before changing Muse.
7. **Low: keep Type and More in one place.** Type is at 8,3 on Home and 8,2 on the Emoji grids. More is at 9,5
   on Home and 0,1 on Emoji. Both come from Smartbox's WhatsApp layout. The Emoji grids are used rarely.

## Website (muse.ai, 2026-11-08, Chrome)

The page suits a grid: the chat is a `role="log"`, 75% of the 51 visible controls have a test id or
`aria-label` (28 test ids), and Muse has a dark mode (Settings > General > Appearance > Mode). One control has
no accessible name, and two inputs are under 24 px high (the message box among them). The page has no
landmarks or headings. The page script does not need them, because it uses test ids and labels.
